## Context

On hosts without hooks (Claude Desktop, web, mobile), the memory skill is
what makes the agent use tiroir: when to search, read, and write (C5c, C7,
W7). [ADR-013](../decisions/ADR-013-adapters-and-skills.md) fixes it as
generated by the core per member, from the schemas of the stores they are
granted: a description of at most 150 tokens in the stores' memory language
naming the drawer types and shared-space topics, and a body explaining the
tools, scoping, confirmation and audience rules, and when to write. It never
names a store the member cannot reach, and it goes stale after a migration or
an access change. Its wording decides whether C7 (9 of 10) and W7 (8 of 10,
and nothing on 5 chatter conversations) hold, so it is written with care and
revised at the exit check (`guides-002`).

## Covers

- C5c (part): the generation, the 150-token description and the staleness
  record; the download from the account page is `skill-002`'s
- S3
- C5 (part): the skill's description stays within 150 tokens; the tool
  definitions are checked by `context-003`
- W7 (part): the body says when to append a log entry, when to propose a
  summary update and when to write nothing; the scripted acceptance run is
  `guides-002`'s

## Scope

Files this task is expected to touch:

- `src/tiroir/core/skill.py`:
  - the skill's text from the member's granted stores and their schemas at
    `main`'s head: `SKILL.md` with a `name` (`tiroir-memory`) and a
    `description` frontmatter, then the body
  - the description in the memory language of the member's stores (French
    and English texts shipped; a member with stores of both languages gets
    both, within the cap), naming each drawer type's `label_plural` and the
    `shared.topics`, never a store's name or a drawer's name
  - the body: what each tool is for (`tiroir_context`, `tiroir_search`,
    `tiroir_read`, `tiroir_write`, `tiroir_status`), calling
    `tiroir_context` first with the user's request when a drawer may be
    named, scoping to the drawers named (X1, X2), the audience rule (writes to
    a team store need the user's confirmation), and when to write: a log
    entry for each new fact, decision, deadline or document received about a
    drawer, a summary proposal when a durable fact changes, nothing for
    chatter (W7)
  - a fingerprint of everything the text depends on (the member's grants and
    each granted store's schema hash), so a change of either makes the
    downloaded skill stale
  - the archive: a zip holding `tiroir-memory/SKILL.md`, as Claude Desktop
    and the web accept for upload
- `src/tiroir/core/migrations/0005_skill.sql` (or the next free number) and
  `src/tiroir/core/serverdb.py`: the fingerprint of the skill each member
  last downloaded
- `src/tiroir/core/api.py`: `MemberContext.memory_skill() -> SkillArchive`
  (records the download), and `status()` reporting `skill_stale`
- `src/tiroir/core/types.py`, `src/tiroir/core/__init__.py`: `SkillArchive`
  (file name, bytes, fingerprint) and the `StatusReport` field
- `tests/unit/core/test_skill.py` (text from given schemas, no store),
  `tests/integration/test_memory_skill.py`

Out of scope:

- the account page and `/account/skill.zip` (`skill-002`)
- the `tiroir_store` `skill` action and `tiroir_status`'s text (`context-003`)
- the project-instructions snippet and upload steps (`guides-001`)
- the init skill (team milestone)

## Acceptance criteria

- For a member granted a store from `accounting-firm`, the description is in
  French, names `Clients` and the shared topics, and is at most 150 tokens by
  the documented approximation; for one granted a store from `developer`
  (`presets-001`, or an English fixture schema until then), it is in English.
- The skill of a member never contains the name of a store they are not
  granted, nor any drawer name or summary text (tested with two members and
  two stores).
- The body names every tool listed above, the team-store confirmation rule,
  and the three write cases of W7, in the store's language.
- After a download, `status()` reports the skill fresh; after a grant on a
  new store, or a change of a granted store's schema, it reports it stale.
- The archive unzips to `tiroir-memory/SKILL.md` with valid YAML frontmatter.
- `mise run check` passes.
