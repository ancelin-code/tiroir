## Context

With the evaluation (`eval-001`), the judged sets (`eval-002`) and the
benchmarks (`bench-001`) in place, this task produces the evidence the
milestone's exit asks for, and the decisions that follow from it:

- **The default model (R4a, ADR-006):** among the five candidates of the
  registry, those whose resident memory, added to the rest of the server
  measured on P6's store, keeps it within 4 GB (P4), and whose full index
  time meets P3, the highest recall@5 on the French set wins, MRR breaking
  ties. The comparison is published in the documentation.
- **The four questions carried from the review of `search-001` (PR #18),
  listed under the `retrieval` milestone of `specs/decomposition.md`:** the
  French stemmer (Snowball against a light, inflection-only stemmer), the
  fusion method (RRF with k = 60 against a convex combination of normalised
  scores) and its parameter, the lexical floor (the "half the content terms"
  rule, with the skeleton review's `relance TVA` case), and bounding
  identifier digit joins (`123 456 789 2 dossiers` gives `1234567892`).
- **The default thresholds** per model, calibrated on the bundled sets, and
  the calibration rule of `eval-001` kept or revised.

Changing a default is a code change in this task; amending ADR-006 and
ADR-007 with the results is part of the pull request, for the project owner
to approve with it.

## Scope

Files this task is expected to touch:

- `src/tiroir/core/embeddings/registry.py`: `DEFAULT_MODEL`, measured
  resident memory and default threshold of each candidate
- `src/tiroir/core/retrieval.py`, `src/tiroir/core/fusion.py`,
  `src/tiroir/core/lexical.py`: the chosen fusion method, parameter and floor
- `src/tiroir/core/textnorm.py`: the chosen French stemmer (a light
  inflection-only stemmer, if it wins, implemented here) and the identifier
  join rule (bounded, if the evidence says so); `textnorm.VERSION` bumped so
  indexes rebuild
- `bench/eval_models.py` (or the bench harness's equivalent): the script that
  runs every candidate and setting on both sets and writes the tables
- `docs/reference/models.md` (new, added to the `nav` of `zensical.toml`):
  the comparison table per model (recall@5, MRR, negative false positives,
  query latency, full-index time on P3's store, resident memory), the
  machine it ran on, and the chosen default
- `specs/decisions/ADR-006-embeddings.md`, `specs/decisions/ADR-007-retrieval.md`:
  dated amendments recording the results and the decisions
- `tests/unit/core/test_textnorm.py`, `tests/integration/test_lexical.py`,
  `tests/integration/test_hybrid.py`: updated for the chosen rules, with the
  `relance TVA` and `123 456 789 2 dossiers` cases as regression tests

Out of scope:

- adding a candidate model outside ADR-006's list
- a reranker (ADR-007)
- changing the judged sets to favour a result (a judgement found wrong is
  fixed and listed in the pull request)

## Acceptance criteria

- `docs/reference/models.md` holds the table for the five candidates on both
  sets, regenerated by one documented command, and names the default; the
  default meets P3 and P4 by `bench-001`'s numbers.
- With the defaults, `tiroir admin eval` on stores created from both presets
  shows hybrid ≥ lexical and ≥ semantic on recall@5 and MRR, and > on at
  least one (V3); every identifier, number and surname query ranks a
  relevant entry first (R2); detection has zero false detections on
  negatives (C3).
- Each of the four questions has a recorded answer with its numbers in the
  ADR-007 amendment, and the code follows it; the `relance TVA` regression
  test shows the chosen floor's effect.
- The registry's default threshold of each candidate is the calibrated one,
  and a store created from a preset reports no `not-calibrated`.
- `mise run docs:build` passes; `mise run check` passes.

## Validation

The comparison command documented on `docs/reference/models.md`, `tiroir
admin eval` on both presets, `mise run docs:build`, then `mise run check`.
